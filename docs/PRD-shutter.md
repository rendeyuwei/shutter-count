# 相机快门次数查询（ShutterCount）需求文档

**状态：** 已确认（需求 + UI）  
**路径：** `https://rende.fun/shutter`  
**仓库：** 新建独立仓库  
**视觉：** 深色主题，可参考 EasyPic token，不强制像素级对齐  

---

## 1. 背景与目标

任德现有站点（含 EasyPic `/easypic`）需新增「上传相机原图 → 读取快门次数」工具页，独立新仓部署，挂同一域名子路径 `/shutter`，不影响现有服务。

**成功标准：** 用户上传一张直出原图后，能看到机身型号、快门次数、拍摄时间（有则显示）；读不到时有明确提示。

---

## 2. 范围

### 做

- 单页 Web：上传 → 解析 → 展示结果 / 失败提示
- 服务端解析 EXIF + 厂商 MakerNote（ExifTool 或同等能力）
- 品牌优先：佳能、尼康、索尼、富士等主流
- 部署：新服务 + Nginx 反代到 `/shutter`（同 ECS）
- 图片临时处理，不长期保存

### 不做（本期）

- 账号体系、历史记录、批量上传
- 强制与 EasyPic 同仓或共用前端工程
- 子域名（除非后续另定）

---

## 3. 用户流程

1. 打开 `/shutter`
2. 拖拽或点击选择一张原图（JPG/JPEG）
3. 进入解析中态
4a. 成功 → 展示机身、快门次数、拍摄时间 →「再查一张」  
4b. 失败 → 明确提示 + 仍展示能读到的机身/时间 →「重新上传」

---

## 4. 功能需求

| ID | 需求 | 说明 |
| --- | --- | --- |
| F1 | 上传原图 | 支持点击 / 拖放；JPG、JPEG；建议提示「相机直出原图」 |
| F2 | 解析快门 | 读 MakerNote / 厂商私有标签中的快门计数 |
| F3 | 结果字段 | **机身型号**、**快门次数**、**拍摄时间**（有则显示） |
| F4 | 读不到 | 文案：`该型号原图可能不含快门信息，或请换一张相机直出的原图再试。` |
| F5 | 隐私 | 临时解析，不长期保存；页脚提示 |
| F6 | 再查 | 成功/失败后可重新上传，回到上传态 |

---

## 5. UI 规格（已确认）

静态原型：`/workspace/shutter-ui/index.html`  
截图：`shot-upload.png` / `shot-success.png` / `shot-fail.png`  
详设：同目录 `DESIGN.md`

### 5.1 视觉 token（默认深色）

- 背景 `#0c0d0f`，表面 `#141619` / `#1b1e22`，文字 `#f4f3ef`，次要 `#a6a8a9`
- 强调色 `#efac4b`，危险 `#ff8f82`
- 字族 Inter / system-ui；圆角 10 / 16 / 24px；卡片最大宽 ~630px
- 品牌标：`SC`（琥珀方块）+ eyebrow `ShutterCount`
- H1：`查看相机快门次数`

### 5.2 状态

1. **上传**：虚线 dropzone「点击或拖放原图到这里」；副文「支持 JPG、JPEG，建议相机直出原图」；隐私「图片仅临时解析，不长期保存」
2. **解析中**：同一区域 spinner +「正在解析原图…」
3. **成功**：文件名 chip；结果卡三行（快门次数大号琥珀数字）；主按钮「再查一张」
4. **读不到**：软警告条 + 部分元数据（机身/时间）；次按钮「重新上传」

## 7. 验收清单

- [ ] `/shutter` 可访问，不影响 `/easypic`
- [ ] 上传 JPG 原图可进入解析并出结果或明确失败文案
- [ ] 成功展示：机身、快门次数、拍摄时间（有则）
- [ ] 失败文案符合 F4；有部分元数据时仍展示
- [ ] UI 四态与定稿截图一致（允许微调，不改信息架构）
- [ ] 图片不落长期存储（或可配置短 TTL 后删除）
- [ ] 至少用 1～2 个主流品牌原图做冒烟验证
