# ShutterCount 全项目 TypeScript 现代化方案

[English](MODERNIZATION.md) | [简体中文](MODERNIZATION.zh-CN.md)

迁移覆盖整个项目的应用逻辑：浏览器、HTTP、解析器、相机映射、Node 工具、启动逻辑及测试，最终统一采用严格检查的 TypeScript。每个阶段都交付可运行、可验证发布与回滚的版本。当前产品继续采用 Fastify、ExifTool、单页交互和单进程部署。

## 迁移范围与完成标准

| 范围       | 目标                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 后端       | 用 TypeScript 明确应用组装、配置、HTTP 路由、完整照片处理流程、诊断及应用独立拥有的 ExifTool adapter          |
| 前端       | Vite 与 TypeScript，拆分上传状态、HTTP 解码、渲染与诊断模块，保留现有视觉设计                                 |
| 共享契约   | 共享结果类型并校验网络数据，统一有效上传限制，明确每种结果允许的字段                                          |
| 测试       | 所有测试实现迁移 TypeScript，保留 Node 测试运行器与有来源说明的 JPEG 样本，补充少量真实浏览器测试             |
| Node 工具  | 冒烟、部署客户端、健康检查、部署接收器及构建工具均迁移 TypeScript，生产工具编译为 JavaScript                  |
| 启动与配置 | 启动逻辑迁移 TypeScript，保留 `bin/start.mjs` 作为稳定的最小 PM2 引导文件，PM2 配置保留其要求的 CommonJS 格式 |
| 其他文件   | HTML、CSS、SVG、JSON、YAML、Bash 保持各自格式，生成的 JavaScript 放入忽略的构建目录                           |

仍需维护的原型脚本与 Bash 内嵌 Node 逻辑也迁移到类型化模块；由 Vite 预览替代的旧原型可以退役。

完成标准：移除 `allowJs`，所有维护中的 TypeScript 均通过严格检查，不用大范围 `any` 或 `ts-nocheck` 绕过迁移，生产应用仅依赖生产依赖即可启动。生成的 JavaScript 与外部工具所需的最小引导文件属于正常运行产物。

## 目标模块结构

```text
src/
  app.ts                 组装应用，不启动监听
  main.ts                启动监听及有时间上限的优雅退出
  config.ts              校验环境变量与显式选项
  photo/                 上传校验、解析及等待完成的清理
  parse.ts               ExifTool 实例所有权与解析诊断
  mapping.ts             纯相机与标签规则
shared/                  结果契约及安全诊断词汇
web/
  index.html
  app.ts                 浏览器入口、上传状态与请求取消
  api.ts                 配置读取与响应校验
  render.ts              使用 textContent 渲染
  diagnostics.ts         隐私安全的反馈
public/                  CSS、图标等静态资源
test/                    TypeScript 回归测试与 JPEG 样本
scripts/                 TypeScript 运维工具与 Bash 发布脚本
tools/                   TypeScript 构建与开发工具
bin/start.mjs            稳定的 PM2 引导入口
dist/                    编译后的应用、工具、测试与前端资源
```

照片模块负责从上传到清理的完整生命周期，路由不重复处理资源管理。真实 ExifTool adapter 与测试替身使用相同 interface，覆盖读取、健康检查和关闭；不同应用实例不再共享全局解析器。

| 2 后端与运行时契约       | 迁移解析器与 HTTP，分离 app/main，配置启动校验，浏览器读取有效上传限制，结果 Schema 校验，解析器归属与关闭，有限并发及排队                       | 错误与超时分类、清理契约、错误配置启动即失败、繁忙响应、实例隔离、优雅退出、诊断不泄露元数据                | 本地完成 |

每个阶段形成独立、可审查的变更。先约束类型，再调整业务行为；保留现有 JPEG 预期、HTTP 状态、请求 ID、隐私规则与 `/shutter` 挂载。修复具体行为时补回归测试，格式调整限定在已迁移的文件内。

## 构建与开发

使用 Node 22.12 或更新版本，CI 继续通过 `.nvmrc` 选择 Node 22。Node 产物使用 ESM 与显式 `.js` 导入路径。Vite 使用相对资源 URL，同一份产物支持 `/shutter`、根路径和自定义前缀。

第一阶段曾使用 `allowJs` 过渡；现已移除 `allowJs` 和 `checkJs`，所有维护中的 TS 源码、Node 工具与测试均在严格检查范围内。前端使用独立的 DOM 类型检查配置，防止意外引用 Node 全局对象。

```bash
npm ci
npm run typecheck
npm run build
npm run test:built
npm start
```

`npm test` 先构建再运行编译后的测试。`npm run dev:server` 使用 tsx 监听后端变化；`npm run dev:web` 使用 Vite 开发前端，将 `/api` 代理到本地 `/shutter/api`。构建产物不提交，由锁文件重新生成。

## 发布与回滚

现有主机流程只安装生产依赖，没有编译步骤。新流程在验证期间安装锁定的开发依赖，依次检查类型、构建、运行编译后的测试，然后裁剪开发依赖，再激活版本。正式应用直接运行编译产物，不依赖 tsx、TypeScript 或 Vite。构建、测试、裁剪任一步失败都必须保留之前的版本。

保持外部已配置的 `current/bin/start.mjs` 路径稳定。将版本 `REVISION` 复制到构建产物，使健康检查报告正确的运行版本。保留精确版本校验、发布锁、软链切换、指定 PM2 进程重启和健康失败回滚。

接收器、Bash 发布脚本及可信健康检查器由 root 管理，位于仓库之外。启用新发布流程前，需要管理员另行安装已审阅的更新；合并不会更新这些安装文件。可信 TypeScript 工具现已构建为 `dist/trusted/` 中只导入 Node 内置模块的独立产物，附带 SHA256 校验清单。固定文件名与安装校验已保留；内嵌 Node 校验迁移为 `deploy-guard.mjs`。

## 验证与运维要求

- CI 在 Node 22 上运行严格检查和完整回归测试，本地尽可能执行相同检查。
- 验证根路径与自定义前缀下的 HTML、JavaScript、CSS、图标，再上传有来源说明的 Nikon 样本。
- 移除开发依赖后，验证编译产物仍可启动。
- 验证激活前安装、构建、测试、裁剪失败，以及激活后健康失败和中断的恢复。
- 增加真实浏览器行为测试，保留映射与隐私分类的快速单元测试。
- 确认锁定版本解决静态资源依赖的安全公告；依赖审计与生产可利用性验证分别判断。
- 生产激活前验证主机脚本安装、可用磁盘与 CPU、实际回滚；本地替身无法证明主机配置正确。

禁止记录照片、文件名、任意 EXIF、原始异常与元数据。限制解析器等待及请求时长，响应完成前清理临时上传，保留清理失败诊断。性能限制依据实际主机容量确定。

## 第二至四阶段的本地交付

后端拆分为 `app.ts`、`main.ts`、`config.ts`、`photo/upload.ts`、`photo/admission.ts` 和 `parse.ts`。应用自行管理 ExifTool；上传生命周期限制为默认 2 个执行中、8 个排队、等待 5 秒。队列满或超时返回 503 / `busy`。临时文件清理发生在释放容量及发送响应之前，日志保留受限诊断字段。

共享协议同时定义编译类型与运行时解码器：前后端校验结果判别字段、有效整数、上限和元数据类型，并剔除未声明字段。`GET /api/config` 提供有效上传字节限制；前端配置失败可重试，恢复前不上传。浏览器拆分为上传控制、API、渲染、诊断和类型模块。

所有测试、冒烟和部署工具已迁移 TS。`npm run test:browser` 使用已安装 Chrome 的隔离会话；构建不下载浏览器。旧 HTML 原型已退役，设计预览使用实际页面的 `?demo` 状态。PM2 保留最小 `bin/start.mjs` 引导；关闭逻辑使用 SIGINT/SIGTERM 与 20 秒期限，主机 PM2 必须核验为 25 秒关闭超时。

2026 年 10 月 11 日的首轮本地验证使用 Node 24.21.0 和 Chrome 155：严格类型和格式检查、238 项回归测试与 9 项 Chrome 浏览器检查通过，依赖审计为 0 个漏洞。独立目录只安装生产依赖，经稳定入口启动后通过精确 SHA、静态资源、有效配置、Nikon 计数 526 及正常退出验证。

已完成的本地阶段保存在 `codex/modernize-typescript` 的迁移快照中，合入 main `7e5237a8888686c187c2e6181c09e28a183c2b37`。PR #4 的百度统计片段原样保留。草稿 PR 准备工作补充真实浏览器取消验收，并拦截浏览器外部请求；生产依赖检查纳入 Node 22 CI 的 `npm run test:production`。CI 在构建前记录版本号，生产检查也会核验构建复制版本号的行为。
