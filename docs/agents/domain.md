# Domain Docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records (ADRs) under `docs/adr/`.

## Before exploring the codebase

Read the root glossary and ADRs relevant to the area being explored.

If either is absent, proceed silently. Domain modeling creates these
documents when terms or decisions are resolved; create them as needed.

## Use the glossary's vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider whether it matches project
language or note the gap for `/domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, identify the ADR explicitly
and explain why its decision should be reconsidered.
